# Mailing App
Приложение Django для управления рассылками, клиентами и сообщениями с разграничением прав доступа для менеджеров и администраторов.

# Описание
* Приложение позволяет:
* Управлять клиентами
* Создавать и редактировать рассылки
* Создавать, просматривать, редактировать и удалять сообщения в рассылках
* Отслеживать статистику по попыткам рассылок
* Управлять правами доступа и ролями пользователей (менеджеры, администраторы)
* Позволяет менеджерам работать только с собственными объектами, а администраторам иметь полный доступ к данным

## Особенности
* Использование Django 5.2
* CRUD интерфейс для клиентов, рассылок и сообщений
* Фильтрация данных по владельцам и правам доступа
* Ограничения на создание, обновление и удаление сообщений менеджерами только по своим рассылкам
* Возможность блокировки пользователей и отключения рассылок администраторами
* Кэширование статистики рассылок для ускорения отображения

## Установка и запуск
Клонировать репозиторий:
~~~
git clone https://github.com/natali83911/mailing_list.git
cd mailing_list
~~~

Создать и активировать виртуальное окружение:
~~~
poetry env use python3.12  # указать нужную версию Python
~~~

Установить зависимости:
~~~
poetry install
~~~

Применить миграции и создать суперпользователя:
~~~
python manage.py migrate
python manage.py createsuperuser
~~~

Запустить сервер разработки:
~~~
python manage.py runserver
~~~

Структура приложения
- models.py — модели Mailing, Client, Message, MailingAttempt с привязкой к владельцу
- views.py — CBV для управления сущностями с проверкой прав через миксины (OwnerRequiredMixin, PermissionRequiredMixin)
- templates/mailing_app/ — шаблоны для списка, форм, подтверждения удаления, статистики
- templatetags/ — пользовательский фильтр is_owner для проверки прав в шаблонах
- urls.py — маршруты для всех представлений
- 
Кэширование статистики рассылок через декоратор cache_page
Права доступа (Permissions)
- can_view_all — право администратора видеть и управлять всеми данными
Менеджерам доступны операции CRUD только над своими объектами
Ограничение создания, редактирования и удаления сообщений согласно владельцу
Доступ к отключению рассылок только для пользователей с правом can_view_all

## Использование
Для доступа к CRUD операциям в интерфейсе используйте стандартные URL и шаблоны, где кнопки управляются через проверку прав и владения объекта
Для создания сообщения менеджер должен быть аутентифицирован и иметь право на добавление сообщений
Статистика доступна только владельцу рассылок с использованием кэширования

Технические требования
Python 3.12+
Django 5.2+
